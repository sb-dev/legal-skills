## 1. Scope and questions

Which existing legal data sources, registries and APIs should `legal-skills` ORCHESTRATE rather than rebuild, for the proving jurisdictions (England and Wales / UK first, EU second, US headline)? Official and open sources first; commercial at headline level.

Questions asked of every source:

1. Does it give stable identifiers and pinpoint URLs?
2. Is in-force / status / currency data machine-readable, or only a banner for humans?
3. What is the update lag?
4. What do the licence and terms say about automated, bulk, AI or "computational" use?
5. Can an agent call it without an account, key or payment? What leaves the machine?
6. Does it close a Stage 5 bounded gap (G2 WIPO, G3 Companies House, G4 no free citator, G8 raw-text route for long EU acts)?

Method. Pages were fetched with `curl` using an identifying User-Agent and converted to plain text locally; JSON / XML endpoints were called directly with public, keyless requests only. `r.jina.ai` was used as a text reader where direct fetch returned 403 (marked "reader"). GitHub metadata came from `gh api`. WebSearch was used only for discovery; two WebSearch summaries are recorded as weak evidence and nothing numeric relies on them. No sign-ups, no keys, no confidential data sent. WebFetch was not used.

Inspection-mode vocabulary in the register: `raw-text` (page or file read as text), `raw-live` (a live keyless API call whose response was read), `reader` (r.jina.ai text rendering of the provider's own page), `gh-api`, `search-summary` (model-written WebSearch summary — weak).

## 4. Overlap with `legal-skills`, and what is missing

**Near-equivalents found in this assignment's territory**

- **GovInfo MCP server** (K-24): the first *official* publisher-run MCP server for legal data. It is retrieval only (search + describe), US only, and GPO itself warns that model QA is still needed. It validates the project's architecture (agent orchestrates an official source) rather than competing with it.
- **CourtListener Citation Lookup** (K-16): a purpose-built anti-hallucination citation verifier — for US case law only. It is the closest existing thing to Stage 5's V1 existence test.
- **Lexis API "Ask / Summarize" endpoints** (K-52): a commercial answer engine behind a sales wall; not orchestrable by an open project.
- Nothing found here overlaps with the project's actual product — the workflow, records, gates and escalation discipline. Every source above is a data layer.

**What is genuinely missing in the landscape**

1. **A free or open UK citator.** Confirmed absent. No API-accessible later-treatment data for UK cases exists, commercial or free.
2. **An AI-permissive licence for UK case law.** The official source bars computational analysis without a separate licence; BAILII bars programmatic use outright. There is no UK counterpart to CourtListener's open corpus.
3. **A UK citation-existence API.** Find Case Law can resolve a neutral citation by URL (`/uksc/2023/42`), which gives a V1 check one judgment at a time, but nothing parses and verifies a block of UK citations.
4. **UK trade mark register API.** Announced, undated. EUIPO has one behind approval; WIPO forbids automation; USPTO needs an identity-verified key. An open-source skill cannot itself run a trade mark register search in any proving jurisdiction today without user-held credentials.
5. **Machine-readable currency for non-gov.uk regulators.** ICO, SRA and (without a token) the FCA expose update dates only as page text.
6. **A thin, tested adapter layer** that turns legislation.gov.uk CLML / effects, CELLAR SPARQL and the GOV.UK Content API into Stage 5 authority records. The raw sources are excellent; nobody appears to have packaged them as agent-ready, record-producing calls. This is glue, not a database — it is within scope and worth building.

## 6. Failure modes and limits observed

1. **Collapsed EU dates.** CELLAR returns entry-into-force and date-of-application as two values of the same property (K-21). A naive adapter takes the first and mis-states when the GDPR applied. The adapter must read the act's final article as well.
2. **Revised ≠ current.** legislation.gov.uk serves a version with `dct:valid` 2026-06-19 *and* an `UnappliedEffects` block in the same response (K-07). Both must be read; the effects feed showed entries modified four days before retrieval.
3. **Old and new documentation disagree.** `/developer/limitations` says secondary legislation is not revised; the newer data documentation has a per-type table; rate limits differ between two official pages (K-02–K-06). Prefer the newer docs; take the stricter limit.
4. **Scanner disagreement on licences.** ClearlyDefined `CC0-1.0 AND MIT` vs deps.dev `MIT` for the same package version (K-47, K-48). Either alone would have produced a confident, possibly wrong, answer.
5. **SPA and bot walls defeat simple fetch.** FCA Handbook returns an empty Angular shell (and the shell again for `/robots.txt`); eCFR docs, UK IPO trade mark search, WIPO Brand DB, BAILII, LawCite, ICLR, SRA and the main EUIPO site all block or challenge a plain client. A fetch tool that then "summarises" such a page will invent content; the skill must detect shell / challenge pages (tiny text, "captcha", "Just a moment") and record a failed retrieval instead.
6. **Large payloads.** GDPR XHTML is 807 KB; a UKSC judgment XML exceeded 256 KB; ClearlyDefined returned 182 KB for one package. Slice by anchor / `eId` locally before anything reaches the model — this also yields exact pinpoints.
7. **Identifier ambiguity.** legislation.gov.uk can return 300 Multiple Choices for one `/id/` URI; Find Case Law says identifiers are not guaranteed unique and warns against parsing meaning out of document URIs; CELLAR returned two work URIs for one CELEX.
8. **Register accuracy.** Companies House states filings are not closely reviewed and that it may annotate doubtful entries; GLEIF data is self-reported; TMview has no legal effect. All are dated facts about what a register showed.
9. **Timestamps that look alike.** GOV.UK `updated_at` (technical) vs `public_updated_at` (editorial); FCL `published` / `updated` / `transform` / `tna-enriched`; legislation `dc:modified` vs `dct:valid`. Each adapter needs an explicit mapping to Stage 5 §7.1 dates.
10. **Moved pages.** The Companies House policy link on its own developer hub now redirects; the Content API exposes this as `document_type: redirect`. `developer.uspto.gov` silently redirects to the new portal; the old OSI API is archived. Link rot is routine even among official sources.
11. **Quota exhaustion mid-task.** A tool session limit interrupted this research run. Workflows need a resumable evidence log (this one resumed from saved raw files without re-fetching).
